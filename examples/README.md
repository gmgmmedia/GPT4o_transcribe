# Transcription Training Examples

This folder contains audio files paired with human-corrected transcripts for training and improving transcription accuracy.

## Purpose

By comparing API-generated transcripts against human-corrected versions, we can identify recurring error patterns and improve post-processing guidance.

## Folder Structure

Each example should be in its own subfolder:

```
examples/
├── README.md
├── {name}/
│   ├── audio.mp3       # The raw audio file
│   ├── corrected.srt   # Human-corrected final SRT
│   └── api_output.srt  # Generated by comparison workflow
```

## Adding a New Example

1. Create a subfolder with a descriptive name:
   ```bash
   mkdir examples/my-example
   ```

2. Add your audio file (MP3, WAV, etc.):
   ```bash
   cp path/to/audio.mp3 examples/my-example/audio.mp3
   ```

3. Add the human-corrected SRT file:
   ```bash
   cp path/to/corrected.srt examples/my-example/corrected.srt
   ```

## Running a Comparison

Ask Claude: **"compare examples/{name}"**

This will:
1. Transcribe the audio using the API
2. Save output to `api_output.srt`
3. Compare against `corrected.srt`
4. Identify error patterns
5. Update CLAUDE.md with learnings

## Example Workflow

```
User: compare examples/podcast-ep1

Claude: I'll run the comparison workflow for podcast-ep1...

[Transcribes audio]
[Compares outputs]
[Reports differences]
[Updates CLAUDE.md with patterns to avoid]
```

## What Gets Learned

The comparison identifies patterns such as:

- **Spelling errors**: Proper nouns, technical terms, names
- **Punctuation issues**: Missing periods, incorrect comma usage
- **Terminology mistakes**: Industry jargon, acronyms
- **Speaker label mapping**: Matching "Speaker 1" to actual names
- **Formatting differences**: Line breaks, subtitle timing

These patterns are added to CLAUDE.md for future post-processing guidance.
